# GDN-3: дизайн (динамическое число матриц-«банков» поверх GDN-2)

## 1. Цель и ключевое решение
Цель: удерживать в разы больше ассоциаций, чем одна матрица D×D, **не ухудшая GDN-2** там, где ёмкости хватало.

Главная идея — **два потока**:

| поток | что считает | роль |
|---|---|---|
| **main** | точный GDN-2 по всей последовательности (одно состояние, h0=0) | гарантия качества: при выключенном архиве слой *тождественен* GDN-2 |
| **banks** | те же k, w·v, β, g, но последовательность разрезана на n=⌊L/C⌋ сегментов; каждый сегмент стартует с **нулевого** состояния → S_j | ёмкость: каждый банк хранит только факты своего сегмента |

Выход слоя: `o = o_main + tanh(γ_h) · o_arch`, где `o_arch` — чтение прошлых банков. При γ=0 — ровно GDN-2 (тест `gate0 == GDN-2`).

### Почему не «сброс состояния на границах сегмента» (схема из первой заготовки)
Сегментный сброс теряет непрерывность (токены у начала сегмента видят пустое состояние). В двухпотоковой схеме непрерывность хранит main, а banks лишь *добавляют* точное хранилище старого. Цена — второй проход ядра (см. §5).

### Точная связь банков и состояния (проверено в numpy, `tests/test_numpy_ref.py`)
Состояние после сегмента: `h_j = A_j h_{j-1} + B_j`, где B_j — состояние сегмента, стартовавшего с нуля (наш банк S_j), A_j — оператор перехода (затухание + стирание). Для β=0 (без стирания) `h = Σ_j diag(exp(G_end − G_j)) S_j` **точно** (ошибка 1e-15). С β>0 добавляется стирание старого новыми ключами — банки его не моделируют; это и есть то, что main-поток покрывает точно.

## 2. Динамическое число матриц
* N = ⌊L/C⌋ растёт с длиной; **параметры не зависят от N** (никаких `probes[MAX_MATS]`): роутер — функция от q и содержимого банка.
* Последний неполный сегмент не образует банк (читать его некому), токены читают только банки j < seg(t) → причинность на уровне токена.
* Один вызов ядра: сегменты складываются в batch-ось (B·n), нет Python-цикла по сегментам.
* Бюджет памяти при стриминге (`BankStore`): `fenwick` (≤ per_level банков на уровень, N ~ log n) и/или жёсткий `budget` (слияние двух старейших). Слияние `S = diag(exp(gsum_new))·S_old + S_new` **точно при β=0**, приближённо при β>0 (ошибка ~43% в тесте с β=1, L=2C, D=32) → слияние — это потеря ёмкости, а не бесплатное сжатие. Для обучения банки всегда точные.

## 3. Чтение (роутинг без доп. параметров на банк)
Для токена t сегмента i и банка j<i:
```
r_j    = scale · (q_t ⊙ exp(G_t − Gend_j)) · S_j          # затухание с конца банка до t (bank_decay)
logit_j = τ_h · rms(r_j)                                  # «уверенность»: банк, реально хранящий ключ, возвращает когерентный вектор
a = softmax([θ_h, logit_1..logit_{i}])                    # θ — null-слот (значение 0): «ни один банк не уверен»
o_arch = Σ_j a_j r_j
```
Реализация — онлайн-softmax внутри `lax.scan` по банкам с `jax.checkpoint`: память O(L·D), FLOP 2·L·D²·n на голову. Почему не центроид-индекс: усреднённый ключ по сегменту — это та же память с ёмкостью D, и ломается в точности на тех нагрузках, ради которых всё затеяно; read-norm использует сам банк как индекс (в numpy-механизме даёт 1.00 вплоть до P=1024).

## 4. Правило выбора размера сегмента C (критично)
Матрица D×D хранит порядка D/2 надёжных ассоциаций. Если в сегменте больше фактов — банк перегружен, и N банков не дадут ×N. Для MQAR (2 токена на пару) и D=128: C=128 → 64 пары на банк. Ядро требует C кратным 128. Для реального текста «число фактов» неизвестно → sweep C ∈ {128, 256, 512, 1024} (docs/EXPERIMENTS.md, M3).

## 5. Стоимость
Слой с банками: main (1×ядро) + bank-проход (1×ядро; выход o сегментов отбрасывается — нужно только финальное S) + чтение 2·L·D²·n. Банки в каждом `bank_every`-м слое: при bank_every=2 примерно +½ ядра на слой в среднем. Оценка «+25–40% времени шага» — **гипотеза**, измеряется `bench/speed.py`. Память остаточных: S (B·H·n·D²·4 Б); при L=64k, C=128, D=128, H=4: n=512 → 512·4·64 КБ = 128 МБ на слой на последовательность.

## 7. Что приближённо / ограничено
* Банки не моделируют стирание между сегментами (его даёт main).
* Факт, разорванный границей сегмента (ключ в j−1, значение в j), в банки не попадает (main его видит). Опция overlap не реализована.
* Landmarks (HOLA-стиль) — экспериментально, только batch-режим; atomic-вариант с `v_new` — копия `pipeline.py` с лишним выходом (проверить `tests --atomic`).
* Стриминг: нет landmarks; точное равенство batch/stream проверяется тестом.
* Нет sparse-диспетчеризации: чтение плотное по n банкам (годится до n≈100–200; дальше — двухэтапный роутинг, M4).

## 8. Риски → диагностика
| риск | симптом | как ловим |
|---|---|---|
| утечка из будущего | «слишком хороший» loss | `causal` тесты на границе и внутри сегмента, с γ≠0 |
| банки перегружены (C велик) | P* не растёт с N | sweep C; oracle-режим MQAR |
| роутер не учится (γ≈0) | γ остаётся ~0, P* как у GDN-2 | лог γ,τ,θ; gate_init=0.1 |
| потеря качества на обычном тексте | val(GDN-3) > val(GDN-2c)+0.005 | M3, 3 seed'а |
| время шага | ×>1.4 | `bench/speed.py`, bank_every=4 |
