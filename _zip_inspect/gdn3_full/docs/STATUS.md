## Сессия 2, часть 2 (приоритет 2, не прогнано)
| Пункт | Итог |
|---|---|
| CCQ по paper | **ИСПРАВЛЕНИЕ: «ложная тревога» было неверным выводом.** Доказано лишь, что post-read и pre-read формы совпадают при ОДНОЙ И ТОЙ ЖЕ Σ. Но в paper (arXiv 2606.01294, abstract проверен) Σ — бегущая ковариация КЛЮЧЕЙ (кривизна лог-партиции softmax), а в коде Σ_S = SSᵀ/‖S‖² строится по состоянию. Это разные операторы ⇒ CCQ по paper НЕ реализован (статус CAVEAT, как в исходном аудите). Нужна ковариация ключей на банк, C_j = Σ decay·kkᵀ (удвоение памяти банка) и точная нормировка/параметризация λ из текста статьи (я видел только abstract). Тест `test_ccq_equals_query_contraction` фиксирует только эквивалентность форм для Σ_S. |
| `n_levels` | `n_levels=0` → авто: floor(log2(slots))+1 (`cfg.n_lv`; без `max_banks` берётся 4096 → 13). По умолчанию остаётся 6. Все обращения переведены на `cfg.n_lv`. Тест `test_parallel_eq_scan_auto_levels` не прогнан. |

## Сессия 3: что показал присланный `gdn3_kit.zip` и проверка формул
**Два разных кода.** `gdn3_kit` (~2500 строк, режимы gdn2/local/hybrid/snap, политики fifo/merge, 19 тест-функций, есть `cache.py`, `segments.py`, `read.py`, `cli.py`, `sim/`) — это БАЗА с историей запусков (Pallas PASS в ноутбуке Pack). Мой `gdn3_full` — независимая реконструкция из лога (другой набор файлов: `ops/archive/layer/mixer`), в неё добавлены 16 модулей. Байтовой/тестовой совместимости с `gdn3_kit` НЕТ: режима `local`/`warm` у меня нет; в kit нет ни одного из модулей A/B/C/D и нет bank_decay (в `read.py/cache.py` нет `exp`). Роутер (energy-ratio + JL-sketch + null) совпадает по формуле; отбор top-k у kit — через порог `>= kth` (при ровных баллах может взять больше k), у меня — через индексы.
Рекомендация: считать kit каноническим, а модули переносить на него по одному с эквивалентностью `gate=0 ⇒ GDN-2`, не наоборот.

**Проверка формул по первоисточникам (через поиск):**
| Что | Результат |
|---|---|
| SSE ур.(7),(8), arXiv 2507.16577 §3.2 | **Подтверждено**: k_t = softmax(top-k(x_t W_k)), S_t = Λ_t S_{t−1} + k_tᵀ v_t. Это ЗАПИСЬ (row-sparse update), а не выбор строк при чтении ⇒ `sse_topk_rows`/`sse_k` (чтение по |q_i|·‖S_i‖) — другая операция. |
| SSE-партиции, balance loss | **Не подтверждено.** Во вставленном тексте формула k^{(i)}=e^{(i)}·softmax(xW_k+e^{(i)}) и формула balance loss в доступных мне фрагментах не найдены; v1 говорит «learnable bias» для выбора партиции, v2 — «write-read gate». Не реализую без текста §3.3. |
| CCQ, arXiv 2606.01294 | Σ = бегущая ковариация ключей — подтверждено (abstract). См. исправление выше. |
| OSDN, Fenwick/Log-Linear, Adaptive λ | В этой сессии НЕ проверялись (формулы из вставленного текста приняты как непроверенные). |
