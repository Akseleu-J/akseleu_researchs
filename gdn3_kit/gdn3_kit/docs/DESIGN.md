# GDN-3: динамическое число матриц состояния поверх GDN-2 (atomic_gdn2) — дизайн

> Статус: **код написан, но не запускался на TPU** (в среде, где он создавался, нет JAX). Проверено: синтаксис и
> undefined-names всех файлов, а также numpy-симуляции ключевых идей (`sim/`). Всё остальное проверит набор
> тестов `tests/` на вашем Kaggle — это первый шаг (см. `KAGGLE.md`). Цифры помеченные «оценка» — прикидки.

---

## 1. Цель и ограничения

Цель: **пул матриц состояния, число которых растёт с длиной контекста (динамически), при этом качество
не хуже GDN-2** (формулировка пользователя: «почти без потерь»).

Что уже установлено в предыдущих отчётах и принято как данность:

* Схема «main → bridge → main» с переносом `h0` **тождественна одной матрице** (chunk-инвариантность ядра) — проверено
  побитово. Ничего нового она не даёт.
* Независимость матриц даёт только (1) **раздельная инициализация/сброс состояния**, (2) **разделение записи**,
  (3) **выборочное чтение**. Якоря `r` внутри ядра — чисто численная деталь и к независимости не относятся.
* Старый роутер с `q_mean` по сегменту нарушал причинность. Здесь все решения принимаются **для токена t по q_t и
  замкнутым (закрытым) банкам**, поэтому причинность проверяема тестом `test_causality`.

## 2. Ключевая идея: «надстройка, а не замена»

«Почти без потерь качества» удобнее всего гарантировать **конструкцией**, а не надеждой на обучение:

```
o_t  =  o_GDN2(t)                              ← точный GDN-2, кумулятивное состояние, как раньше
      + tanh(γ_h) · scale · Σ_j a(t,j) · q_t S_j   ← чтение top-k закрытых банков (j < seg(t))
```

При `γ = 0` модель **совпадает с GDN-2 до бита** (тест `test_hybrid_gate0_equals_gdn2`). Обучение может только
добавить вклад архива; если архив бесполезен, градиент уведёт `γ` в ноль.

Режимы (`G3Config.mode`):

| режим | кумулятивный проход | банки | цена (оценка) | когда |
|---|---|---|---|---|
| `gdn2` | все головы | — | 1× | baseline |
| **`hybrid`** (по умолчанию) | все головы (точный GDN-2) | **независимые** сегментные состояния `S_j` с `h0 = h_init`, строятся у `arch_heads` голов | 1× + `Ha/H`× ядра | гарантия «не хуже GDN-2» |
| `snap` | все головы, сегментами через `lax.scan` | снимки кумулятивного состояния на границах сегментов | ≈1× | самый дешёвый; банки не независимы |
| `local` | головы `[Ha:]` кумулятивные, головы `[:Ha]` — независимые сегменты (+warm-up `W`) | те же независимые состояния | 1× | экономия; теряет глобальный контекст у архивных голов → качество надо мерить |

`arch_heads=Ha < H` — ручка стоимости: архив только у части голов (например, 1 из 4 → +25% ядра в `hybrid`).

### Почему `tanh(γ)` стартует с 0.1, а не с 0
Градиент по параметрам роутера пропорционален значению гейта. При `γ=0` роутер получает нулевой градиент до тех
пор, пока `γ` сам не сдвинется (медленно, выглядит как «роутер не учится»). `gate_init=0.1` оставляет модель
«почти GDN-2» и сразу даёт сигнал роутеру. Тесты на эквивалентность обнуляют гейт явно.

## 3. Независимые банки

Сегмент `j` = токены `[jC − W, (j+1)C)`; его банк `S_j` — финальное состояние ядра, запущенного на этом сегменте
из **обучаемого** `h_init` (параметрическая память в стиле SDM). Все `n = ceil(L/C)` сегментов — это **batch-ось**
(`B·n`, `fold_overlap`), поэтому это **один вызов ядра без Python-цикла по сегментам** и никакого нового Pallas-кода.

* `W` — warm-up (ваш «bridge», но **до** сегмента, а не после; в `hybrid` не нужен, `W=0`; в `local` включайте как
  отдельный ablation: стоит `+W/C` вычислений). Выходы warm-up отбрасываются.
* Хвост последовательности дополняется нулевыми токенами (`k=0, β=0, w=0, g=0`) — это точные no-op для состояния,
  поэтому длина **любая** (`forward` сам паддит до кратного `align` и обрезает), а число банков `n` динамично.
* Причинность на уровне токена: токен сегмента `s` читает только банки `j < s` (замкнуты целиком в прошлом).
* Градиент течёт через ядро (custom VJP) в `q,k,v,w,β,g` и в `h_init`.

## 4. Роутер: адресация по содержимому через «энергию отклика»

Скор банка `j` для запроса `q` (единичной нормы):

```
score_j = τ · log( ‖q S_j‖² / ( ‖S_j‖_F² / D ) )  −  λ · log(1 + age)        (+ «null»-опция)
```

* `E_q‖qS_j‖² = ‖S_j‖_F²/D` — ожидание для случайного запроса. Отношение ≈ 1 для банков, **где ключа нет**, и ≫ 1 для
  банка, где он лежит, **независимо от заполненности банка** — поэтому банки сравнимы.
* `‖q S_j‖²` оценивается JL-скетчем `‖q (S_j R)‖²`, `R ∈ R^{D×m}` (фиксированная гауссова): индекс стоит `D·m`
  вместо `D²` на банк. По умолчанию `m = D/2`; `sketch_dim=0` — точный.
* `null`-логит (обучаемый) позволяет **ничего не читать**, если ни один банк не подходит; `Σ a_j = 1 − p_null ≤ 1`.
* `top_k` банков получают разреженный softmax; запрет на «размазывание» (условие 3 из отчёта).
* `age`-prior мягко предпочитает свежие банки (`λ`, обучаемый).

Центроидный роутер из прошлого плана **не используется**: среднее многих случайных ключей ≈ 0, индекс выходит
слепым (в отчёте это был риск №4). Энергия-отношение смотрит на *реальное содержимое матрицы*.

### Проверка (numpy, `sim/router_sim.py`, дельта-правило β=1, 16 банков, D=128, top-1 / top-2)

| пар в банке | скетч m=32 | m=64 | точный |
|---|---|---|---|
| 16 | 1.00 / 1.00 | — | 1.00 / 1.00 |
| 32 | 0.97 / 1.00 | — | 1.00 / 1.00 |
| 42 (D/3) | 0.96 / 1.00 | 1.00 / 1.00 | 1.00 / 1.00 |
| 64 (D/2) | 0.88 / 0.95 | 0.81 / 0.93 | 1.00 / 1.00 |
| 96 (3D/4) | 0.55 / 0.76 | 0.60 / 0.79 | 0.89 / 0.97 |

(D=64: «надёжный» предел — 16–24 пары; 32 пары — только точным роутером.) Вывод: роутер надёжен до **~D/3** пар в банке,
скетч `m=D/2` достаточен до D/3, при плотнее набитых банках берите `sketch_dim=0`. 64 банка при 42 парах: top-1 ≥ 0.9.

## 5. Ёмкость сегмента — главный выбор `C`

Матрица `D×D` с дельта-правилом хранит порядка `D` ассоциаций, но **искать** по ней надёжно можно до `~D/3`.
В MQAR пара = 3 токена ⇒ `C ≈ 3·D/3 = D` токенов: для `D=128` берите **`C = 128`** (минимум для Pallas, `bt=128`),
для `D=64` на Pallas сегмент `128` уже перегружен (42 пары > D/3=21) — используйте `D=128`.
Для реального текста «фактов на токен» меньше — `C=512` разумный старт (grid `{128, 256, 512, 1024}`).
Ошибка отчёта №1 (`C=2048` при `D=128` — 5× перегрузка) исключена: `segments.capacity_pairs()`.

## 6. Динамическое число матриц

Три уровня динамики, все реализованы:

1. **По длине (обучение/prefill).** `n = ceil(L/C)` определяется формой входа; `forward` принимает любой `L`.
   Хвостовой неполный сегмент — паддинг-no-op. `segments.plan_segments(L, C, n_max)` подбирает `C` под бюджет `n_max`
   (при превышении `C` растёт ⇒ ёмкость на банк падает, использовать осознанно).
2. **Стриминг (декодирование).** Кэш растёт: каждые `C` токенов замкнутый банк дописывается в архив
   (`cache.append_bank`, `jit`-совместимо, формы статичны: `max_banks` слотов + счётчик + `seg`-ид слота).
   Чтение — `top_k` из `N` банков, индекс скетчей хранится рядом (`T`, `‖S‖²`), на токен стоит
   `N·D·m + k·D²` на голову (разреженный gather `top_k` банков).
3. **Бюджет памяти.** При `cnt == max_banks`:
   * `fifo` — выбросить самый старый банк;
   * `merge` — сложить два самых старых в один «sink»-банк (суперпозиция: лоссово, но сохраняет след всего прошлого,
     масса `Σ S` сохраняется — `test_archive_policies`).
   `bench/archive_policy.py` показывает деградацию качества при `N < n` (в т.ч. память `N·Ha·D²·4·layers`).

Не реализовано сознательно (требует изменения ядра, в среде без TPU это слишком рискованно):

* **Адаптивные границы по насыщению** (закрывать банк, когда он «полон»). Нужны сегменты переменной длины и
  `reset`-флаг в Pallas-ядре. Сейчас — фиксированный `C`, динамика только по `n`.
* **Лог-линейная схема (Fenwick):** банки уровня ℓ = суммы `2^ℓ` соседних независимых банков, читаются ≤ `log₂ n`
  блоков; считается через префиксные суммы `P_j = Σ_{i<j} S_i` (блок = `P_end − P_start`) — без ядра. Лоссово
  (суперпозиция), хорошо ложится на `merge`. План M4.
* **Разреженная диспетчеризация** для `n ≳ 64` в обучении (чтение сейчас плотное по `n` с маской, треугольная
  стоимость `L·n/2·D²`; Python-циклы по банкам ⇒ держите `n ≲ 64`, иначе растёт время компиляции).

## 7. Стоимость (на голову, оценка; `D=128`)

| компонент | FLOP (MAC) | заметка |
|---|---|---|
| кумулятивное ядро | как GDN-2 | не меняется |
| банковый проход (hybrid) | как GDN-2 на `Ha` головах | batch-ось `B·n` |
| индекс (скетч) | `L·(n/2)·D·m` | `m=64` ⇒ ½ от чтения |
| чтение | `L·(n/2)·D²` | плотно по `n` с маской; decode — только top-k |
| память банков | `n·D²·4 Б` на голову/слой | `D=128`: 64 КБ/банк/голова |

Память декодирования: `layers·Ha·N·D²·4 Б` (`D=128, Ha=2, layers=2, N=256`: 33.5 МБ).

## 8. Согласованность параллельного и потокового путей

Главный источник скрытых багов — расхождение `forward` и `decode_step`. Их семантика совпадает по построению
(`gdn_step` — общая рекурренция; банки `A/Bw` ведут warm-up в точности как `fold_overlap`; проверено numpy-симуляцией
`sim/stream_check.py`, разница 0.0) и контролируется тестами `test_decode_equals_parallel` (все режимы, скетч и точный
роутер, неполные хвосты) + `prefill` (параллельный выровненный префикс + рекуррентный хвост).

## 9. Контроли и протокол экспериментов

Обязательные:

* **≥ 3 seed'а**, порог значимости = 2–3 σ (в первом отчёте σ не измерялась).
* **iso-state**: `n` банков `D×D` = `n·D²` чисел; честный соперник — один `D' = D·√n` (`n=4 ⇒ D'=256`). Для `n=4`
  (`L=4096, C=1024`): `--cfg gdn2_wide:mode=gdn2,d_head=256,n_heads=2`.
* **iso-FLOP** (сравнение времени/токен из `bench/speed.py`).
* **oracle-режим** (`--oracle`): роутеру подсовывается истинный сегмент. `oracle ≫ обычный` ⇒ чинить роутер;
  `oracle ≈ обычный` ⇒ узкое место — ёмкость банка/забывание.
* **SWA-baseline** (для M3: окно 512–1024) — без него «длинный контекст» не оценивается честно.

Этапы:

| этап | что | критерий |
|---|---|---|
| **M0** | `tests/run.py --backend both` зелёный; `bench/speed.py` | все PASS; compile-time и μs/токен записаны |
| **M1** | `bench/mqar_capacity.py`, `hybrid128` vs `gdn2`, 3 seed | `P*(hybrid) ≥ 2·P*(gdn2)` и gap > 3σ; oracle-диагностика |
| **M1b** | то же: `local`, `snap`, `arch_heads=1`, `seg ∈ {128,256,512}`, `top_k ∈ {1,2,4}` | ablation-таблица, выбор дефолта |
| **M2** | `bench/lm_position.py` (enwik8, L=8k, eval 32k) | ранние позиции: `Δ bpb ≤ +0.01` к GDN-2 (нет потерь); поздние (≫C): ниже GDN-2 |
| **M3** | `bench/archive_policy.py` | деградация `fifo/merge` при `N < n` приемлема/измерена |
| **M4** | реальный LM (BPE, 100M+), NIAH, Fenwick, sparse dispatch, адаптивные границы | — |

Замечание про MQAR: условие «факт и запрос далеко» достигается раскладкой `[факты][filler][запросы]`: факты — в первых
сегментах, запросы в последних. Чтобы читать их, *необходим* архив (кумулятивное состояние GDN-2 при `P ≫ D` теряет
факты — это и есть измеряемый эффект).

## 10. Риски и диагностика

| риск | симптом | проверка |
|---|---|---|
| роутер схлопнулся на свежий банк | `read_age ≈ 0` | `forward(..., want_stats=True)`; oracle-режим |
| банк перегружен | `acc` падает при `P > n·D/3`; oracle тоже низкий | уменьшить `C`; `arch_heads` ↑ |
| гейт ушёл в 0 | `gate≈0` в stats | архив бесполезен на этой задаче (это честный результат) |
| скетч слишком грубый | oracle > обычный при плотных банках | `sketch_dim=0` |
| утечка из будущего | «слишком хороший» loss | `test_causality` на границах и внутри сегмента |
| рассинхрон parallel/stream | `test_decode_equals_parallel` падает | сравнить `step_read` и `archive_read` |
| точность Pallas-пути | pallas-vs-serial > 3e-3 | `test_backend_matches_serial`; `dot_mode="highest"` |
| компиляция | минуты на большой `n`/`nc` | `seg ≥ 128`, `n ≲ 64`; ядро компилируется ~60–140 с (как в NB19) |
| OOM | HBM 16 ГБ | `remat=True`, меньше `bsz`/`L`, `arch_heads` меньше |

## 11. Что исправлено относительно прежних отчётов

1. Причинность: роутинг по токену, банки только закрытые, тест на границах.
2. `tanh(0)` блокировал роутер → `gate_init=0.1` (+ явное обнуление в тестах).
3. `C=2048@D=128` → `C=128` (D/3 пар), sweep `{128…1024}`.
4. `W=0` по умолчанию (warm-up — отдельный ablation).
5. Роутер: энергия-отношение + `null`, а не центроид; чтение при `n=64` оценено честно (плотное по `n`).
6. Честный jit-бенчмарк (`bench/speed.py`): компиляция отдельно, прогрев, медиана, `block_until_ready`.
7. Тест эквивалентности градиентов разреза (`test_split_grads`) вместо `sum|grad|`.
8. Поканальный decay с log-сеткой полураспадов 16…16384 токенов (`decay_init`) — иначе «узкое место» могло быть
   горизонтом, а не ёмкостью (W9 из разбора).

## 12. Дерево решений по итогам M1

```
P*(hybrid) ≥ 2·P*(gdn2)?
 ├─ да, oracle ≈ обычный → хорошо, масштабировать (M2/M3)
 ├─ да, oracle ≫ обычный → улучшить роутер (скетч m↑, sketch_dim=0, top_k↑, температура)
 └─ нет
     ├─ oracle ≫ обычный → роутер не находит: sketch_dim=0, C меньше, больше шагов
     ├─ oracle ≈ обычный (низкий) → ёмкость банка: C меньше (D/3 пар), D больше, пересмотреть decay
     └─ и gdn2 с d_head=D·√n так же хорош → выигрыш только по FLOP (тоже результат; см. iso-state)
```

## 13. Ограничения этой версии

* Не запускалось на TPU; допуски тестов (`TOL`) для TPU выставлены ослабленно (bf16-проходы по умолчанию).
* `local`-режим при `arch_heads=H` лишает архивные головы глобального состояния — ожидаемо хуже `hybrid`.
* Скетч `R` — фиксированный (seed 1234), не обучаемый.
* Оптимизационные гиперпараметры (`lr=1e-3` для MQAR, `6e-4` для LM) — разумные дефолты, не результат тюнинга.
* Контентная запись (MoM/SSE), Fenwick, адаптивные границы, sparse dispatch — вне объёма (см. §6).
